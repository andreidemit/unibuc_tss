Categorisirea testelor

Numerele de mai jos folosesc cazurile pytest colectate. Unele teste apar in mai multe categorii, deoarece acelasi caz poate verifica atat comportamentul functional, cat si o frontiera sau un mutant.

Tip de testare Cate teste Teste / fisiere relevante Ce demonstreaza
Functionala / black-box 13 deterministe + 500 random valide test_manual_basic.py, test_ai_improved_cases.py, test_random_valid_inputs_match_independent_oracle Verifica rezultatul calculului pe baza specificatiei: standard, express, same_day, premium, rural si combinatii.
Structurala / white-box 12 cazuri pentru SUT + 4 pentru analizorul de risc test_mutation_focused_cases.py, test_risk_prioritizer.py Vizeaza ramuri, conditii, ordinea regulilor, rotunjirea si punctele critice detectate in cod.
Valori de frontiera 7 cazuri deterministe test_non_positive_numeric_inputs_are_rejected, test_positive_boundary_values_are_accepted, test_validation_error_messages_are_exact Testeaza frontiera lui 0 pentru greutate si distanta: 0 invalid, valori imediat pozitive valide.
Partitionare de echivalenta 13 deterministe + 500 random valide standard/express/same_day, regular/premium, urban/rural Acopera clasele valide si invalide pentru tip livrare, tip client si tip zona.
Cazuri exceptionale / validare 12 deterministe + 120 random invalide test_negative_weight_is_rejected, test_unknown_types_are_rejected, test_random_invalid_inputs_match_independent_validation_oracle Confirma ca inputurile invalide produc ValueError si mesaje corecte.

Mutation-focused 12 cazuri test_express_multiplier_is_exactly_one_point_five, test_same_day_multiplier_is_exactly_double, test_rural_fee_is_added_after_premium_discount Include asertiuni stricte care omoara mutanti pentru comparatii, multiplicatori, reduceri, taxe si mesaje.
Rotunjire si precizie numerica 1 caz determinist + cazuri random cu zecimale test_rounding_to_two_decimals_is_stable, test_random_valid_inputs_match_independent_oracle Detecteaza erori in round(cost, 2) si in calculele cu valori fractionare.

Ideea principala a experimentului

Coverage-ul arata ce linii si ramuri au fost executate, dar nu garanteaza ca asertiunile sunt suficient de puternice. Mutation testing-ul introduce modificari mici in cod si verifica daca testele le detecteaza. In acest proiect, testele asistate de IA au fost folosite pentru a transforma mutantii greu de detectat in cazuri concrete de testare.

Mutatie dificil de observat manual De ce poate scapa Test adaugat dupa analiza cu IA
weight_kg <= 0 devine weight_kg < 0 Un test cu greutate negativa trece in ambele variante; problema apare la valoarea de frontiera 0. Teste pentru 0, 0.01 si valori pozitive foarte mici.
Multiplicatorul 1.5 pentru express este modificat Un test care verifica doar ca express este mai scump decat standard poate ramane verde. Test cu valoare asteptata exacta pentru express.
Ordinea reducerii premium si a taxei rurale este afectata Testele separate pentru premium si rural nu verifica interactiunea dintre reguli. Test pentru combinatia express + premium + rural.
Rotunjirea finala este eliminata sau modificata Cazurile cu valori intregi nu expun diferente de zecimale. Test cu valori fractionare: 1.333 si 2.777.
